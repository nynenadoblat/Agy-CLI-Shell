# Antigravity Launcher: Правила и протокол разработки

Данный документ фиксирует критические инженерные стандарты проекта **AntigravityLauncher**. Любой агент или разработчик обязан строго соблюдать следующие требования:

---

## 1. Кодировка и Windows PowerShell 5.1 (UTF-8 BOM)
* Лаунчер выполняется в среде **Windows PowerShell 5.1**, которая по умолчанию читает файлы без BOM как **Windows-1251 (ANSI)**.
* Все файлы с расширением `.ps1` в проекте **ОБЯЗАНЫ иметь сигнатуру UTF-8 BOM** (`0xEF, 0xBB, 0xBF`).
* Запрещено сохранять `.ps1` файлы в "UTF-8 без BOM" — это приводит к поломке AST-парсера на кириллических литералах и падению при старте.
* Для автоматической проверки и наложения BOM используйте `verify_fast.ps1`.

---

## 2. Изоляция тестов и защита пользовательских данных
* **Строжайший запрет на затирание `launcher_config.json`**: автоматические тесты никогда не должны удалять или перезаписывать боевой файл конфигурации пользователя.
* Для любых тестов обязательно устанавливайте переменную окружения:
  ```powershell
  $env:ANTIGRAVITY_CONFIG_PATH = Join-Path $PSScriptRoot "scratch/test_config.json"
  ```
  Лаунчер автоматически считывает эту переменную и работает с изолированным тестовым файлом, сохраняя вкладки пользователя нетронутыми.

---

## 3. Быстрый шлюз верификации (Fast Verification Gate)
Перед завершением задачи или фиксацией изменений запускайте:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File verify_fast.ps1
```
Скрипт выполняет следующие проверки за несколько секунд:
1. Автоматический аудит и наложение UTF-8 BOM на все `.ps1` файлы.
2. Полная проверка синтаксиса через AST-парсер (`[System.Management.Automation.Language.Parser]`).
3. Валидация структуры `launcher_config.json`.
4. Изолированный прогон `AntigravityGUI.ps1 -Headless` (проверка успешной сборки и инициализации WPF UI без вывода окна).

---

## 4. UI-производительность и асинхронность
* **Виртуализация сообщений**: при рендеринге диалогов отображаются последние 25 сообщений с кнопкой подгрузки ранней истории. Запрещено единовременно вставлять тысячи блоков в `FlowDocument` на UI-потоке.
* **Неблокирующее завершение**: остановка фоновых `PowerShell` Runspace-потоков и сборка мусора должны выполняться в `[System.Threading.ThreadPool]::QueueUserWorkItem`, не замораживая UI.

---

## 5. Запрет догадок и обязательный первоисточник CLI/API (Zero-Assumptions Protocol)
* **Абсолютный запрет на синтетические квоты**: Запрещено внедрять вымышленные лимиты, таймеры сброса по полуночи UTC или приблизительные проценты (`~100%`).
* **Только прямой API**: Данные о квотах, состоянии моделей и ошибках обязаны считываться исключительно из первоисточника — команды `agy.exe -p "/usage" --output-format json`.
* **Исследование до кодинга**: Любая интеграция с внешней утилитой или CLI начинается с изучения ее интерфейсов (`--help`, `/help`, встроенные команды, JSON-форматы), а не с предположений о том, как устроен сторонний сервис.

---

## 6. Запрет инлайн-экранирования PowerShell (Zero Inline-Escaping Friction)
* **Запрет многострочных `-Command`**: Запрещено передавать длинные скрипты с кавычками, блоками кода и условиями через параметр `powershell -Command "..."`.
* **Всегда через `.ps1` файл**: Любой вспомогательный или тестовый скрипт сохраняется в `scratch/<task>.ps1` с UTF-8 BOM и выполняется через `powershell -File scratch/<task>.ps1`. Это исключает синтаксические ошибки парсера Windows и экономит ходы агента.

---

## 7. Двухуровневая модель тестирования (Two-Tier Test Gate)
* **Промежуточный гейт**: на каждом шаге разработки запускается ТОЛЬКО `verify_fast.ps1` (6 сек, синхронно).
* **Финальный регресс**: тяжелый скрипт `verify_launcher.ps1` (56 тестов) запускается строго один раз перед сдачей задач Класса 2 (Major). **Для задач Класса 1 (Micro) запуск тяжелого сьюта категорически запрещен.**

---

## 8. Атомарные коммиты и защита от сброса (Mandatory Atomic Commit & Anti-Wipe Gate)
* **Коммит каждого принятого шага**: После подтверждения работоспособности любой законченной фичи агент ОБЯЗАН немедленно зафиксировать изменения через `git add -A; git commit -m "feat/fix: ..."`. Запрещено накапливать пул незакоммиченных возможностей в рабочем дереве.
* **Строжайший запрет деструктивного чекаута (`git checkout <file>`)**: Категорически запрещено сбрасывать рабочие файлы через `git checkout <file>` или `git reset --hard` без предварительного создания именованной резервной ветки (`git checkout -b backup_...`) или коммита. Любой сброс вслепую приравнивается к саботажу.
* **Физическая проверка перед отчетом**: Проверять реальное наличие кода функций и обработчиков в файле на диске, а не полагаться на черновики в `scratch/` или память контекста.

---

## 9. Автоматический триаж сложности и протокол быстрых правок (Self-Triage & Fast-Path Protocol)

Агент **ОБЯЗАН САМОСТОЯТЕЛЬНО** классифицировать любую входящую задачу перед началом выполнения и применить соответствующий шлюз:

### Класс 1: Micro / Cosmetic (Быстрый шлюз Fast-Path)
* **Критерии**: правка верстки, стилей, цветов, изменение текстов, шаблонов форматирования строк, исправление опечаток или локальные изменения (< 5 строк изолированного кода) без изменения публичных контрактов и архитектуры ядра.
* **Лимит операций**: задача обязана решаться **за 1–2 вызова инструментов**.
* **Прямое редактирование**: строго через инструмент `edit_file` напрямую в целевом файле. **Категорически запрещено** создавать промежуточные `scratch`-скрипты, генераторы патчей или вспомогательные утилиты для микро-правок.
* **Запрет оверинжиниринга**: запрещено самовольно модифицировать дисковые кэши, базы данных или смежные подсистемы, о которых пользователь явно не просил.
* **Шлюз тестирования**: валидация выполняется **ИСКЛЮЧИТЕЛЬНО** через быстрый синтаксический шлюз `verify_fast.ps1` (6 сек). **Категорически запрещено** запускать тяжелый регрессионный сьют `verify_launcher.ps1` или вспомогательные E2E-тесты на задачах Класса 1!
* **Результат**: правка -> `verify_fast.ps1` -> атомарный `git commit` и `push`. Время выполнения: до 1–2 минут.

### Класс 2: Major / Architecture (Полный инженерный шлюз Full-Gate)
* **Критерии**: рефакторинг ядра, новые подсистемы, интеграция API/CLI, межпроцессное взаимодействие (IPC), изменение логики потоков/Runspace, исправление зависаний.
* **Протокол**: исследование, детальный план, сохранение нетривиальных скриптов в `scratch/` с UTF-8 BOM, промежуточная валидация через `verify_fast.ps1` и один финальный прогон полного сьюта `verify_launcher.ps1` перед сдачей.
