# Antigravity Launcher: Правила и протокол разработки

Данный документ фиксирует критические инженерные стандарты проекта **AntigravityLauncher**. Любой агент или разработчик обязан строго соблюдать следующие требования:

---

## 1. Кодировка и Windows PowerShell 5.1 (UTF-8 BOM)
* Лаунчер выполняется в среде **Windows PowerShell 5.1**, которая по умолчанию читает файлы без BOM как **Windows-1251 (ANSI)**.
* Все файлы с расширением `.ps1` в проекте **ОБЯЗАНЫ иметь сигнатуру UTF-8 BOM** (`0xEF, 0xBB, 0xBF`).
* Запрещено сохранять `.ps1` файлы в "UTF-8 без BOM" — это приводит к поломке AST-парсера на кириллических литералах и падению при старте.
* Для автоматической проверки и наложения BOM используйте `verify_fast.ps1`.

---

## 2. Изоляция тестов и защита пользовательских данных
* **Строжайший запрет на затирание `launcher_config.json`**: автоматические тесты никогда не должны удалять или перезаписывать боевой файл конфигурации пользователя.
* Для любых тестов обязательно устанавливайте переменную окружения:
  ```powershell
  $env:ANTIGRAVITY_CONFIG_PATH = Join-Path $PSScriptRoot "scratch/test_config.json"
  ```
  Лаунчер автоматически считывает эту переменную и работает с изолированным тестовым файлом, сохраняя вкладки пользователя нетронутыми.

---

## 3. Быстрый шлюз верификации (Fast Verification Gate)
Перед завершением задачи или фиксацией изменений запускайте:
```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File verify_fast.ps1
```
Скрипт выполняет следующие проверки за несколько секунд:
1. Автоматический аудит и наложение UTF-8 BOM на все `.ps1` файлы.
2. Полная проверка синтаксиса через AST-парсер (`[System.Management.Automation.Language.Parser]`).
3. Валидация структуры `launcher_config.json`.
4. Изолированный прогон `AntigravityGUI.ps1 -Headless` (проверка успешной сборки и инициализации WPF UI без вывода окна).

---

## 4. UI-производительность и асинхронность
* **Виртуализация сообщений**: при рендеринге диалогов отображаются последние 25 сообщений с кнопкой подгрузки ранней истории. Запрещено единовременно вставлять тысячи блоков в `FlowDocument` на UI-потоке.
* **Неблокирующее завершение**: остановка фоновых `PowerShell` Runspace-потоков и сборка мусора должны выполняться в `[System.Threading.ThreadPool]::QueueUserWorkItem`, не замораживая UI.
